# Фонарщик — notes for Claude

Mobile top-down shooter/roguelite on **Phaser 4 + TypeScript + Vite**. The hero walks dark catacombs with a lantern,
auto-shoots the nearest monster, collects 3 light shards per level to open the exit.
`README.md` (Russian) is the human guide: file map, reading order, "how to add…" recipes, practice tasks.

## Commands

```bash
npm install
npm run dev        # vite --host, port 5173 (falls back to 5174+ if busy — read the actual port from output)
npm run typecheck  # tsc --noEmit — strict, noUnusedLocals/Parameters are on
npm run build      # typecheck + vite build into dist/
```

There are no tests. "Done" = `npm run typecheck` passes + `npx vite build` succeeds + (for visual changes) a look in the browser.
The project is **not a git repository** — there is no history to diff against or revert to; be careful with overwrites.

## Conventions (follow them)

- **Russian** for code comments, UI strings, README. Identifiers in English.
- This is a **learning project**: comments explain *why* and name the Phaser concept (see the header comment of any file).
  Match that density in new code; a new Phaser technique deserves a row in the README table "Главные идеи Phaser".
- **Keep README.md in sync**: file tree under "Структура", recipes under "Как добавить…", debug tips. Update it in the same change.
- **Data lives in `src/data/`** as plain objects without Phaser (enemies, levels, upgrades, potions). Balance numbers go there
  or in `src/config.ts` (`DEPTH`, `COLOR`, `RULES`), never inline in systems.
- Systems never import `GameScene`; weapons get a `WeaponHost` interface. `GameScene` wires systems together and owns the frame order
  (`update()` → physics → `lateUpdate()` on `POST_UPDATE`).
- Everything subscribed in `create()` must be unsubscribed on `Phaser.Scenes.Events.SHUTDOWN`; per-run counters reset in `init()`
  (the scene object is reused across restarts).
- Use `dt` in seconds (already clamped to 1/30 in `GameScene.update`); frame-rate-independent decay is `Math.pow(k, dt * 60)`.
- `Stats` (`data/upgrades.ts`) is the persistent run state copied between levels. **Temporary effects must not mutate stats** —
  derive them (see `Player.moveSpeed` / `Player.fireDelay` + `Player.buffs` for potions).

## Graphics pipeline

- Image assets live in `public/assets/` and are registered in **`src/art/sheets.ts`**:
  `SHEETS` (spritesheets + animations, one row per animation) and `IMAGES` (plain images, e.g. `tiles`).
  `BootScene.preload()` → `loadAssets()`, `create()` → `createTextures()` + `createAnimations()`.
- Everything else is drawn in code in `src/art/textures.ts`. `makeTexture` **skips keys that already exist**, so loading a PNG under
  the same key (e.g. `enemy-ghoul`) replaces the code-drawn version automatically. Remove the dead canvas code when you do.
- Current file assets: `hero.png` (32px, idle/walk/hurt), `rat.png` (24px, run/bite, texture key `enemy-rat`),
  `tiles.png` (7×32px strip, order = `TILE_INDEX` in `world/LevelMap.ts`), `potions.png` (3×16px, frame = `POTIONS[k].frame`).
- Characters are drawn **facing right**; code mirrors with `flipX` (with a 0.2 threshold to avoid jitter).
- Physics circle offset is computed from the frame: `this.width / 2 - radius` — don't hard-code it.
- Sheet-based enemies use a single glowing `eye` overlay at `SHEETS[key].eye` (offset from center, facing right). The head must stay
  at the same pixel in every frame or the glow drifts.
- Placeholder art is generated by dependency-free Node scripts in **`tools/art/`** (`node tools/art/<name>.mjs` overwrites
  `public/assets/<name>.png`). The user may have repainted a PNG by hand — check before regenerating (see the `pixel-art` skill).
- `pixelArt: true` is set in `main.ts`; no smoothing.

## Phaser 4 specifics (differs from Phaser 3 tutorials)

- `RenderTexture` needs `rt.render()` after draw commands (`systems/Darkness.ts`).
- `setTintFill()` is gone → `setTint(c).setTintMode(Phaser.TintModes.FILL)`.
- WebGL only; Canvas renderer is deprecated. `tilemap.createLayer` may return a GPU layer type — cast as in `GameScene.createTilemap`.
- Official topic guides ship with the package: `node_modules/phaser/skills/<topic>/` (animations, tilemaps, physics-arcade,
  loading-assets, v3-to-v4-migration, …). Read the relevant one before using an unfamiliar API.

## Debugging

In the browser console: `game.scene.getScene('Game')` is the live scene, e.g. `.player.stats.blades = 5`,
`.player.drink('frenzy')`. `debug: true` in `src/main.ts` shows physics bodies.

## Project-local helpers

- Skills (`.claude/skills/`): `add-sprite` (wire a PNG/spritesheet in), `pixel-art` (generate placeholder art),
  `add-content` (enemy / weapon / potion / upgrade / level / tile recipes), `verify-game` (check a change end to end).
- Subagents (`.claude/agents/`): `phaser-reviewer` (review a change against these conventions),
  `pixel-artist` (make or revise placeholder art), `game-balancer` (analyze balance numbers).
